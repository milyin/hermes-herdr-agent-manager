# Caller API

This skill supports native Windows and Linux with CPython 3.10+, a compatible `hermes-herdr-pane-manager` in the active profile, and at least one configured backend: Codex app-server or Hermes ACP. On Windows the Herdr server must find native `codex.exe` or `hermes.exe` on its `PATH`. All pane creation and lock checks go through the pane manager's public CLI. A private receiver owns one backend per pane and talks to it over stdio. The caller uses a same-user Windows named pipe or Linux abstract Unix socket to talk to the receiver. The skill does not type prompts into terminals or adopt arbitrary shells or agents.

Prefix each command with `python -I -B <skill-directory>/scripts/agent_manager.py` (`python3` on Linux if needed). Specify `--instance SESSION --workspace WORKSPACE_ID` on every operation and add `--pane PANE_ID` except when provisioning. The pane manager's `workspaces` operation can discover workspace IDs.

| Command | Extra required arguments | Result |
| --- | --- | --- |
| `provision` | `--cwd ABSOLUTE_PATH` | `pane_id`, `cwd`, `agent`, `status: ready`. Optionally provide `--agent codex\|hermes` (default `codex`), `--group`, and `--suffix`. |
| `run` | Matching `--agent codex\|hermes`, `--cwd ABSOLUTE_PATH`, and `--prompt TEXT` or `--prompt-stdin`. `--model MODEL` is required for Codex and optional for Hermes. | `thread_id`, `turn_id`, `model`, and `status: accepted` (Codex native admission) or `status: submitted` (ACP request written; outcome not yet known). |
| `steer` | `--prompt TEXT` or `--prompt-stdin`. `--turn-id TURN_ID` is only for exact active Codex steering. For an idle follow-up, pass `--thread-id THREAD_ID` and optionally `--after-turn-id TURN_ID` from the last receipt. | Both backends support idle follow-ups. A bound follow-up checks the saved IDs and idle state before submitting. Returns the same result fields as `wait`. |
| `change-model` | `--model MODEL` | `model`, `applies: next_turn`. Rejected while a turn is active. Codex applies the override on the next submission; Hermes calls its ACP model setter. Hermes accepts `provider:model` IDs or model IDs understood by its ACP server. |
| `get-remaining-tokens` | `--agent codex` | Codex only. Account rate-limit windows `primary` and `secondary`, each with `remaining_percent`, `window_minutes`, and UTC `reset_at` if reported. This is account usage, not an exact token balance. |
| `check-quota` | None (`--agent codex` may be supplied) | Read-only planning result: the quota windows, `usable_windows`, `behind_windows`, and `hold` (`null`, `quota_behind_pace`, or `quota_unavailable`). No native turn is started. |
| `wait` | `--turn-id TURN_ID` | Reads completion without submitting. Codex returns `thread_id`, `turn_id`, and `answer`. Hermes returns `thread_id`, `turn_id`, `status: completed`, and `session_output`. |
| `recover` | None | Codex only. Resume the exact saved thread after the Codex process exits. Returns `thread_id`, `status: resumed` when idle. Sends no prompt. |

`steer` and `wait` accept `--seconds` (1–600; default 120). On `turn_pending`, keep the identified turn ID and wait rather than resending. Hermes `thread_id` is its ACP session ID; its `turn_id` is a manager-issued correlation ID for this receiver. If the Hermes connection is lost, inspect the session in Hermes; the manager does not automatically recover or replay it. For Codex, `recover` verifies that the process exited before resuming the existing thread. Neither backend transfers a session between panes or automatically retries a failed or paused turn.

The receiver rejects a mismatched bound thread or prior turn without sending the prompt. A receiver started from an older version does not support bound follow-ups. It rejects the request; never retry it without the binding flags. `--thread-id` cannot be combined with the active `--turn-id` option.

Before a Codex `run` or idle `steer`, the receiver reads its own account quota again. Each window with a valid remaining percentage, duration and future reset must have at least as much quota remaining as its fraction of time remaining. Missing, malformed, or expired windows do not count. For example, with two days left in a seven-day window, 50% passes and 10% holds. If no window is usable, or a checked window expires before the prompt write, the receiver refuses with `quota_unavailable`. If any usable window is behind pace, it refuses with `quota_behind_pace`. Neither refusal submits the prompt. This is not a token reservation across panes. Active-turn steering, `wait`, and Hermes ACP do not use Codex pacing.

An explicitly authorized `--override-quota` on `run --agent codex` or idle Codex `steer` skips the local pacing check for that submission only. It does not override provider limits, pane locks, thread binding, or sandbox rules. Do not retry a quota refusal automatically with the override. New Codex runs and idle follow-ups sent by the updated CLI require an updated receiver; do not retry against a receiver that lacks the quota-aware operation.

Hermes ACP v1 correlates the prompt completion, not individual output chunks. Treat `session_output` as observed session text, not an exact answer to one admission. Do not submit to the managed session from another Hermes client while a turn is running. Concurrent input or session notices can mix with the stream; consult Hermes for authoritative history.

For Codex, the manager requests workspace-write sandboxing with networking off unless the caller explicitly authorized `run --network`. Complete any required Windows sandbox setup outside this skill. Hermes uses the selected profile's provider, tools, and approval policy; the ACP working directory is not a filesystem or network sandbox. `--network` is rejected for Hermes. The manager never approves ACP requests, selects an explicit offered rejection when available, and refuses further mutations after `approval_required`. If denial was not confirmed, inspect the pending request in Hermes. The manager does not forward slash commands or change either backend's global settings.

The manager refuses to act on a zoom-locked or ambiguously identified pane. Pane verification and agent submission are separate operations; they are not atomic with human zoom. The receiver is same-user only (peer UID on Linux, user SID and an owner-only ACL on Windows), not a security boundary between untrusted programs running as the same OS user. Scope this to trusted work and protect the account and skill paths.

The CLI emits UTF-8 JSON: `{"ok":true,"result":{...}}` on success (exit 0), or `{"ok":false,"error":{"code":"...","message":"..."}}` on operational failure (exit 1). Usage errors exit 2. Agent protocol traffic is not copied into the pane; the pane hosts the receiver and its backend, not an interactive TUI. Close a finished receiver pane through the pane manager after confirming it is idle and preserving any work. Binding receipts are not used to recover across receiver death.

Use `--prompt-stdin` to keep prompt text out of the process argument list. Prompts are limited to 32 KiB UTF-8 and local protocol frames to 1 MiB. If Codex reports no rate-limit snapshot, the quota call fails; an individual window or reset date is `null` when Codex does not report it.

Protocol references: [Codex App Server](https://developers.openai.com/codex/app-server) and [Hermes ACP](https://hermes-agent.nousresearch.com/docs/user-guide/features/acp).
